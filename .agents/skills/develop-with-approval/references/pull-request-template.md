# Pull Request本文テンプレート

## 背景と目的

解決する問題と、この変更が必要な理由を記載する。

## 主な変更内容

- 利用者から見た変更
- 内部実装の変更
- 追加・更新したテストや文書

## 設計上の判断

- 責務の配置と依存関係
- 採用案を選んだ理由
- 主な代替案とトレードオフ

## 影響範囲

- UI、API、状態管理、DB、認証、外部サービス
- 互換性と回帰リスク
- migrationや環境変数の有無

## 実行したテスト・検証

- [ ] format
- [ ] lint
- [ ] typecheck
- [ ] unit test
- [ ] Storybook/browser test
- [ ] build
- [ ] その他の対象固有検証

各項目にコマンドと結果を記載し、未実施項目には理由を書く。

## 手動確認

- 確認した操作と結果
- 確認に必要な環境やデータ

## UI変更

- スクリーンショットまたは確認方法
- mobile、tablet、desktop、キーボード操作の確認結果

UI変更がなければ「なし」と記載する。

## 残っている課題・制約

- 既知の制約
- 今回の対象外
- follow-upが必要な事項
