## 作業モード

- 既定: ローカルエージェントは **確認モード**、Cloud Agent は **PRモード**（`AGENTS.md` の「作業モード」）
- 依頼に「commitして」「PRにして」「PRモード」がある場合、または Cloud Agent 起動指示で PR まで求められている場合は **PRモード**
- 確認モード中にユーザーが PR 操作を指示したら PRモードに切り替える

## Gitと前提

- ベースbranch（依頼に合わせて main または staging、未指定なら main）、作業branch候補、commit方針
- PRモードでは作業開始前の fetch と最新の origin/<ベース> からの分岐、PR 作成・更新前の再 fetch・ベースからの遅れ・差分範囲を確認する。遅れていれば merge / rebase を提案して指示を待ち、履歴書き換えは個別承認を得る
- staging向けではmainの未取り込みと検証状況を確認する。未取り込みがあれば影響と、同期するか現在のstagingで進めるかの判断事項を示す。同期はユーザーが行う
- 確認モードからPRモードへの移行時、未コミット変更があれば勝手にbranchを切り替えず移行方法を提案する
- `main` / `staging` への直接 push・merge は行わない。**PRモード**のときだけ作業branch の push と指定されたベース向け PR を行う（`AGENTS.md`）
- staging で確認した変更を `main` へ出す手順は `AGENTS.md` の「Git（stagingで確認した変更をmainへ出す）」を参照する
- コードから推測した前提とユーザー判断が必要な事項
