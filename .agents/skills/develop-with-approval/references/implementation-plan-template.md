# 実装計画テンプレート

承認前に次の項目を省略せず提示する。該当しない場合は「なし」と理由を記載する。

## タスクの理解

- 解決する問題、完了条件、対象外

## 現状の関連実装

- 責務とデータフロー
- 関連ファイル、設定、テスト、既存パターン

## 実装方針と代替案

- 採用する手順、責務の配置、既存設計との整合理由
- 検討した選択肢、トレードオフ、不採用理由

## 変更範囲

- 変更・新規・削除予定ファイルと理由
- UI、API、状態、DB、認証、外部サービス、互換性への影響

## リスクと検証

- 技術、セキュリティ、性能、アクセシビリティ、レスポンシブ、migrationのリスクと対策
- 追加・更新テスト、実行するlint・型チェック・テスト・build、手動確認、実行不能な検証

## Gitと前提

- ベースbranch、作業branch候補、commit方針
- ローカルbranch、commit、引き渡しの予定
- GitHub・remote操作は実行しないこと
- コードから推測した前提とユーザー判断が必要な事項

## 承認依頼

上記の範囲、リスク、Git・外部操作を含めて進めてよいか、明示的な承認を求める。
