# 自己レビューチェックリスト

変更に該当する項目をすべて確認する。問題を見つけた場合は修正、再検証、差分全体の再レビューを行う。

## 要件と変更範囲

- 要件と完了条件を満たしている
- 承認された範囲を逸脱していない
- 変更が必要以上に広がっていない
- ユーザーの既存変更を上書き、stage、commitしていない
- 不要なコード、コメント、TODO、デバッグ出力、生成物が残っていない

## 設計と保守性

- 既存のディレクトリ構成、命名、コーディング規約に沿っている
- UI、ロジック、データ取得、永続化の責務が分離されている
- 依存関係が一方向で循環していない
- 重複実装や過剰な抽象化がない
- 将来の変更点が適切な責務へ閉じている

## 正しさと型安全性

- `any` や不必要な型アサーションがない
- null、undefined、空配列、空文字、最小値、最大値を考慮している
- 外部入力と永続化データをruntime validationしている
- 非同期処理、競合、loading、二重送信を考慮している
- エラーを握りつぶさず、利用者に適切に通知している

## セキュリティとデータ

- 認証と認可を混同していない
- 所有者条件やアクセス制御がサーバー側にある
- SQL更新・削除に適切な条件がある
- 秘密情報、個人情報、tokenをコード、ログ、テスト、PRへ含めていない
- XSS、インジェクション、過剰な情報開示を招かない
- migrationの前後互換性とロールバック可能性を考慮している

## UI品質

- キーボード操作、focus、label、ARIA、色だけに依存しない表現を確認した
- mobile、tablet、desktopでレイアウトを確認した
- loading、empty、error、disabled状態を確認した
- 不要な再レンダリングや高コスト処理がない
- 画像や大きな依存によるbundle・表示性能への影響を確認した

## テストと文書

- 正常系、境界値、異常系、回帰リスクを十分にカバーしている
- テストが実装詳細ではなく利用者から見た振る舞いを検証している
- 変更に関係するlint、型チェック、テスト、ビルドを実行した
- 省略・失敗した検証の理由と未確認事項を記録した
- README、環境変数例、API、運用手順の更新要否を確認した

## Git差分

- `git diff --check` が成功している
- stagedとunstagedの両方を確認した
- rename、削除、生成物、lockfile変更が意図どおりである
- commit対象が自分の変更だけである
- PR本文の変更内容と検証結果が実態に一致している
